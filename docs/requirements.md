# 加密云同步需求

状态：产品需求合同；版本 `1.0-draft.1`；更新：2026-09-23。服务端 `0.1.0` 已实现，验证及未完成事项见 [服务端验收](server-acceptance.md)；客户端要求仍需应用实现。接口见 [文档入口](index.md)。

## 1. 目标与不可混淆的概念

| ID | 必须达到的行为 |
| --- | --- |
| R01 | 用户主动开启后，在同一个 GitHub 账号下恢复配置、服务 API 密钥、词典、风格和历史文本。默认关闭。 |
| R02 | 设备内先加密再上传；服务器只保存密文及运行所需的最小元数据。GitHub 登录不代替加密密码。 |
| R03 | 新设备首次恢复需要 GitHub 登录和加密密码；本机已安全保存解密密钥时，后续同步可自动进行。 |
| R04 | 以 GitHub numeric ID 绑定数据；改用户名不丢数据，同名的新账号不能取得旧账号数据。 |
| R05 | 服务代码与协议必须开源。安全目标转成可检查的约束和验收，不承诺“永不被攻破”。 |

这里的“全量”指下表中**全部受支持的逻辑配置及历史数据**，不是打包用户目录，更不是上传整个操作系统钥匙串。只同步几个主题字段的旧 `/me/sync` 合同不能满足此需求。

## 2. 同步内容

| 数据 | 是否进入加密快照 | 恢复规则 |
| --- | --- | --- |
| 应用偏好、界面语言、字号、主题、胶囊、录音、输出、翻译、选区、更新偏好 | 是 | 通过现有设置校验和保存接口应用；未知的新版本字段必须保留或报告不支持，不能静默丢弃。 |
| ASR / LLM / Omni 渠道、模型、排序、启用状态、接口协议、额外请求头 | 是 | 渠道稳定 ID 与凭据引用一起恢复，不按显示名称去重。 |
| 服务 API Key、App ID、Access Key、Secret Key、API Token 等用户填写的服务凭据 | 是 | 从凭据库导出逻辑账户；解密后写回目标设备的系统凭据库。不得将整个密钥库的操作系统加密文件直接复制到另一设备。 |
| 词典、自定义词汇预设、纠正规则、风格包文本及其图标 | 是 | 保留稳定 ID、内容和关联；图标重新分配本地路径。 |
| 听写历史、速记文本、历史中的模式/时间/来源/错误等元数据、活动统计 | 是 | 保留 ID，避免重复；正常保留策略不得在恢复时无提示删掉云端内容。 |
| 麦克风选择、快捷键、窗口位置、本地模型目录、Agent 路径及其他设备相关设置 | 是，放入加密的设备配置档案 | 同一设备可恢复；跨系统时先保留为来源设备档案，只应用本机支持且通过校验的字段。Windows 模型配置不能在 macOS 冒充可用。 |
| GitHub/OAuth 登录态、同步访问令牌、第三方 OAuth 刷新令牌、会话 Cookie | 否 | 每台设备自行授权；恢复相应渠道后显示“需要重新登录”。**普通服务 API Key 不属于此例外。** |
| 云同步加密密码、派生密钥、系统钥匙串/Keystore 文件、设备私钥、TLS 配对私钥与远程输入 PIN | 否 | 不跨设备复制；同步解密密钥只按用户选择保存在本机安全存储。 |
| 操作系统权限、设备授权、当前云同步开关和隐私确认记录、同步队列/基线/锁 | 否 | 本机独立管理；恢复不能授权麦克风、开启自动执行 Agent，或替用户打开云同步。 |
| 模型权重、原始录音、视频、临时文件、缓存、日志、可执行文件 | 否 | 本批不做媒体/模型云盘。历史仅同步文本与元数据；缺少原音频时显示“此设备无录音”，不能提供假播放按钮。 |

客户端必须维护明确的导出登记表。每个持久化配置字段均须归入“可恢复设置”“设备档案”或“上述排除项”，不能使用模糊的“其他不支持内容”作为遗漏理由。新增持久化字段时，同步分类是交付条件之一。

完整快照超出 [协议限额](encryption-protocol.md) 时保留本地数据和待同步状态，显示 `payload_too_large`；不得截断历史、删 API Key 或静默跳过文档来满足限额。

## 3. 开启、首次提示与恢复

### 3.1 主动开启

1. 设置 → 权限与数据 → 云同步显示默认关闭的开关及同步范围。
2. 用户选择开启，阅读隐私说明并确认；未确认前不得上传快照。
3. 复用已有 OpenLess GitHub 登录确认身份，后台换取短期同步会话并读取云端元信息。只有未登录或原授权失效时才进入统一登录流程，不另建 OAuth App 或要求二次授权。
4. 云端为空：设置并确认加密密码，展示首份备份范围，再创建快照。
5. 云端已有快照：输入原加密密码，解密并校验。先展示恢复预览和差异；不得用本机初始默认配置覆盖旧云端数据。
6. 用户确认恢复或处理合并冲突；成功写入本地后才显示完成。
7. 用户可选择“在此设备记住解密密钥”，默认勾选，但必须在确认页明确说明。取消勾选后，重启需再次解锁；锁定期间不能上传或恢复。

“记住密钥”只使用系统安全存储，并绑定服务地址、GitHub numeric ID、vault ID 和 key ID。安全存储读取被拒绝时显示锁定/授权错误，不降级到普通文件保存。

### 3.2 配置完成后的首次提示

- 每个安装实例在第一次具备新加密同步能力、完成初始服务配置后，最多自动提示一次；不是每次启动或每次升级都提示。
- 传统管线：当前可用 ASR 和 LLM 的配置均完成，且本次凭据读取成功。无需 API Key 的本地 ASR 按真实引擎能力判断，不能为了提示要求填写不存在的密钥。
- 多模态管线：有效 Omni 配置完成即可，不要求额外配置 ASR 和 LLM。
- 主窗口已就绪、配置保存完成、没有录音/输入/恢复任务时才显示。凭据读取失败、仍在引导或保存中的状态不能触发。
- “暂不开启”记录本次提示已处理，保持关闭；用户以后从设置主动开启。
- 新设备欢迎流程同时提供主动的“从云端恢复”入口，允许在填写服务 API Key 前登录并恢复，避免要求用户重新填写已经备份的密钥。
- 原有旧云同步用户也必须重新确认新的同步范围，因为本协议首次包含服务密钥和历史，不能根据旧登录态自动迁移上传。

### 3.3 建议采用的产品文案

> 我们尊重你的隐私。配置、服务 API 密钥和历史文本会先在此设备上用你的加密密码加密，再上传到云端。服务器不会收到你的加密密码或解密密钥。请妥善保管密码；如果密码遗失且没有已解锁的设备，我们无法恢复加密内容。

确认项：`我了解同步包含服务 API 密钥和历史文本，并已妥善保存加密密码。`

补充说明须清楚展示：服务器仍能看到 GitHub 账号标识、密文大小、版本、同步时间及必要访问记录；设备本身被控制或密码过弱仍可能导致数据泄露。关闭同步不会删除云端备份；“删除云端备份”是独立操作。

此处是产品隐私说明和启用确认文案，不声称已经形成法律审定的合同或“绝对免责”条款。

## 4. 密码与解锁

- 至少 12、最多 128 个 Unicode 字符；必须包含 ASCII 数字、大写字母和小写字母，允许符号。
- 在本地拒绝常见弱密码，包括 `12345678`、常见数字序列、简单重复和 `Password123` 等变体。明确建议更长且唯一的密码，不能把满足字符组合当成安全保证。
- 密码规则、规范化和 KDF 参数以 [加密协议](encryption-protocol.md) 为唯一来源。密码不能发送到服务器验证强度；服务器因此不能证明第三方客户端确实执行了本地强度检查。
- 密码错误或密文验证失败：本地配置、凭据和历史保持原状，不覆盖云端，不改成未加密同步。
- 改密码必须验证当前密码，读取并合并最新内容，用新盐、新 key ID 和新密码重新加密整份快照，原子提交。其他设备下次同步需要使用新密码解锁。
- 不提供服务端找回密码或解密后门。忘记密码时，可从仍可用的本机数据重新建库，但必须明确确认旧云端密文将无法沿用。

## 5. 同步时机与失败处理

| 事件 | 行为 |
| --- | --- |
| 已开启且已解锁的应用启动 | 一次同步任务：先读云端版本，必要时恢复/合并，再上传本机变化。数据未变化时完成检查即可，不强制生成同内容新版本。 |
| 一项受支持配置、凭据、词典、风格或历史成功持久化 | 标记变更；仅在同步已开启、已登录且已解锁时调度上传，其他状态保留本地现状。连续操作去抖 750 ms，连续变更最多延后 5 秒。 |
| 一次写入正在上传时又发生变更 | 保留更高的本地变更代次；前一次成功不能清掉后一次的待同步标记。任务完成后处理这次已发生的新变更。 |
| 上传失败、断网、请求结果未知 | 保留本地现状、同步基线、变更代次、请求密文和操作 ID；不改写为成功。下一次启动、实际变更、手动重试或网络恢复事件再处理。 |
| `429` / 服务暂不可用 | 记录 `Retry-After` 或本地最短间隔，禁止提前重试；只在下一个有效事件到来时重试，不启动定时上传循环。 |
| 用户手动“立即同步” | 按同一版本、幂等与冲突规则执行，不绕过锁定状态。 |
| 关闭同步 / 注销 | 停止调度；撤销本地会话、清理记住的解密密钥，保留用户配置。已经发出的请求可能提交，必须保留结果核对信息。 |

**不设每隔 N 分钟同步的任务，不扫描无变化的文件定期上传。** 变更去抖、单次请求超时和 GitHub 登录协议要求的短期轮询不属于周期同步。

优先使用仓储“保存成功”事件，不依赖界面按钮点击。文件监听只补充外部修改：处理原子替换后的最终文件，忽略临时文件与自己的恢复写入。比较规范化内容，而不是仅看修改时间。恢复、无变化重写和状态文件更新不能形成“下载→写文件→上传”的循环。

## 6. 多设备冲突与本地恢复

- 服务器看不到 JSON 字段，不能替客户端合并。客户端持有最后成功同步的基线，解密远端后做三方比较。
- 不同设置键、不同稳定 ID 的新增条目可以合并；同一键被两边改动、删除与修改相撞、同一渠道/凭据/风格同时变化，必须报告冲突并由用户选择。不能按设备时钟悄悄覆盖。
- 没有共同基线的新设备不能把“本机没有该值”当成用户删除；已有非空本机配置与云端不同的部分必须进入恢复/合并预览，由用户决定。
- 渠道元数据与关联凭据、风格内容与图标按一个逻辑单元处理，不能混合成半份有效配置。
- 历史和速记按稳定 ID 合并；删除需要加密的删除标记，不能因为离线设备重新上传而复活。删除标记未安全回收前计入快照限额。
- 本地恢复先完整下载、校验、解密、校验逻辑文档并生成预览，再统一应用。配置文件、内存状态与系统凭据库必须可恢复到同一个版本。
- 系统凭据写入失败不能显示“其他设置恢复成功，所以整体成功”。必须回滚或进入明确的 `recovery_required` 状态并保留恢复材料；重启后能继续恢复/回滚。
- 基线、待解决冲突和恢复日志可能包含服务密钥，必须加密保存在本机，不能生成明文的 sync-baseline.json 或密钥回滚文件。恢复尚未取得最终结果时，锁定/注销必须先完成提交或回滚，再清理解锁材料。
- 跨设备绝对路径、麦克风 ID、平台专用模型和操作系统权限不能直接生效。未知或本机不支持的来源配置保留在加密档案内，显示需要本机选择的项目。
- 平台专用的本地 ASR 渠道及其启用/排序状态属于来源设备档案；目标平台不支持时不得进入启用队列或替换当前活动服务。通用本地模型的选择可以作为“待下载”恢复，但不把未同步的模型权重标为已安装或测试通过。
- 删除云端后，其余设备收到删除状态应暂停自动上传，保留本地数据；只有用户明确重建备份，才能再次创建云端快照。

## 7. 关闭、删除与可见状态

显示状态：关闭、需要登录、需要解锁、就绪、待同步、同步中、存在冲突、上次失败、结果待确认、需要恢复处理。成功时间只能在服务器确认本次操作、且客户端验证返回结果后更新。

“关闭同步”和“删除云端备份”分别提供；删除要求再次确认，必须带最后读取的版本。删除成功后在线接口立即不能返回被删密文，保留不含内容的版本墓碑以阻止旧设备回写。服务不得保留用户可读取的旧快照版本；灾备副本最长 30 天清除，运行方必须在上线说明中公开此保留期并验证清除流程。

退出账号后不得把 A 账号的待同步数据上传给 B。切换账号要隔离队列、基线和安全存储；不能仅替换请求头。

## 8. 验收条件

| 编号 | 可复现检查与合格结果 |
| --- | --- |
| A01 | 默认关闭、首次提示拒绝、关闭后改设置：没有私有快照上传。 |
| A02 | ASR/LLM/Omni 以及无需密钥的本地 ASR 引导：提示时机正确，每个实例只提示一次，读取失败不触发。 |
| A03 | 用包含全部登记配置、各类服务密钥、历史、词典、图标的样本往返：逻辑内容一致；排除项未出现在解密快照中。 |
| A04 | 观察服务请求、错误、日志、数据库与运营导出：无密码、派生密钥、服务密钥明文或私有历史正文。GitHub 认证令牌只在认证交换阶段短暂处理。 |
| A05 | 错密码、换账号、改盐/nonce/AAD/密文、截断内容、超额输入：明确失败，本地和云端已有正确状态不变。 |
| A06 | 上传提交后故意丢响应，再用相同操作 ID 重试：只产生一个版本，返回原操作结果。 |
| A07 | 两个设备同时修改不同键、同一键和删除/修改：分别自动合并、显示冲突和显示冲突；不丢数据、不复活删除项。 |
| A08 | 上传中继续改设置、离线退出再启动、网络恢复、429：新变化和待处理请求都保留，无周期重试循环。 |
| A09 | 注入每一步文件/凭据写入失败及进程退出：恢复有明确结果，可继续或回滚，不报告伪成功。 |
| A10 | Windows 配置在 macOS 恢复：保留来源档案，平台专用模型/路径/权限不被当成本机就绪。 |
| A11 | 改密码与旧设备并发上传：只有一个 CAS 成功；旧密钥不能继续写新头，旧设备重新解锁，数据保持完整。 |
| A12 | 删除后离线旧设备重连：不会自动重建；切换账号不会串数据；改 GitHub 用户名不影响归属。 |
| A13 | 开源交付包含协议向量、跨平台互操作、认证隔离和恢复故障测试；独立安全审查完成后方可对外启用。 |
